## 1. 概述

### 1.1 平台简介
任务调度平台（TaskScheduler）是一个分布式任务调度系统，旨在提供可靠、高效、可扩展的任务调度解决方案。平台支持多种任务类型，包括但不限于：
- 定时任务（Cron表达式）
- 一次性任务
- 依赖任务（DAG工作流）
- 延迟任务

### 1.2 主要特性
- **高可用性**：基于主从架构，支持故障自动转移
- **水平扩展**：支持动态增减Worker节点
- **任务监控**：实时监控任务状态和性能指标
- **失败重试**：支持自动重试和手动重试机制
- **任务依赖**：支持复杂的任务依赖关系（DAG）
- **多语言支持**：提供Java、Python、Go等SDK
- **Web管理界面**：直观的任务管理和监控面板

### 1.3 适用场景
- 批处理作业调度
- 数据处理流水线
- 业务流程自动化
- 系统维护任务
- 消息队列消费者调度

### 1.4 技术栈
- **调度器**：Quartz Scheduler
- **消息中间件**：Apache Kafka / RabbitMQ
- **数据存储**：MySQL / PostgreSQL + Redis
- **服务注册**：Zookeeper / etcd
- **监控**：Prometheus + Grafana
- **容器化**：Docker + Kubernetes

### 2.2 核心组件

#### 2.2.1 调度器（Scheduler）
- 负责解析任务调度配置，生成触发器
- 维护任务调度状态，触发任务执行
- 管理任务依赖关系，执行DAG调度
- 提供故障转移和负载均衡机制

#### 2.2.2 Worker节点
- 接收并执行具体任务
- 向调度器报告任务执行状态
- 支持动态扩缩容
- 提供任务执行环境隔离

#### 2.2.3 任务存储服务
- 持久化任务定义和配置
- 记录任务执行历史和日志
- 提供任务查询和统计接口

#### 2.2.4 消息队列
- 解耦调度器和Worker节点
- 实现异步任务分发
- 支持任务优先级和重试队列
- 保证消息可靠传递

#### 2.2.5 Web管理界面
- 任务创建、编辑、删除
- 实时监控任务执行状态
- 系统配置和参数调整
- 用户权限管理

### 2.3 数据流

1. **任务提交**：用户通过API或Web界面创建任务
2. **任务存储**：任务定义持久化到数据库
3. **调度触发**：调度器根据触发器生成执行计划
4. **任务分发**：调度器将任务信息发送到消息队列
5. **任务执行**：Worker从队列获取任务并执行
6. **状态更新**：Worker将执行结果上报给调度器
7. **结果存储**：执行结果持久化到数据库
8. **监控展示**：Web界面展示实时状态和统计信息

- **调度器服务器**：2核CPU，4GB内存，50GB磁盘
- **Worker节点**：4核CPU，8GB内存，100GB磁盘（可根据任务资源需求调整）

- **操作系统**：CentOS 7.x+ / Ubuntu 18.04+

## 5. 核心概念

### 5.1 任务（Task）
任务是调度平台的基本单元，代表一个可执行的工作单元。任务包含以下属性：
- **任务ID**：唯一标识符
- **任务名称**：任务描述性名称
- **任务类型**：SHELL、JAVA、PYTHON、HTTP等
- **任务内容**：具体的执行脚本或代码
- **调度配置**：执行时间、频率、触发条件
- **执行参数**：环境变量、输入参数
- **资源需求**：CPU、内存、磁盘需求
- **超时设置**：最大执行时间
- **重试策略**：失败后的重试配置

### 5.2 触发器（Trigger）
触发器定义任务的执行时机，支持以下类型：

#### 5.2.1 Cron触发器
使用Cron表达式定义周期性执行：
```json
{
  "type": "CRON",
  "expression": "0 0/15 9-17 * * ?",  // 工作日9:00-17:00每15分钟执行
  "timezone": "Asia/Shanghai"
}
```

#### 5.2.2 固定间隔触发器
```json
{
  "type": "FIXED_RATE",
  "interval": 60000,  // 每60秒执行一次
  "initialDelay": 0
}
```

#### 5.2.3 一次性触发器
```json
{
  "type": "ONCE",
  "scheduledTime": "2024-01-01T00:00:00Z"
}
```

#### 5.2.4 事件触发器
```json
{
  "type": "EVENT",
  "eventType": "DATA_ARRIVAL",
  "eventSource": "kafka://topic1",
  "filter": "payload.size > 1000"
}
```

### 5.3 工作流（Workflow/DAG）
工作流是一组相互依赖的任务集合，以有向无环图（DAG）形式组织：
```json
{
  "workflowId": "data-pipeline",
  "name": "数据处理流水线",
  "tasks": [
    {
      "taskId": "extract",
      "name": "数据抽取",
      "dependencies": []
    },
    {
      "taskId": "transform",
      "name": "数据转换",
      "dependencies": ["extract"]
    },
    {
      "taskId": "load",
      "name": "数据加载",
      "dependencies": ["transform"]
    }
  ]
}
```

### 5.4 任务实例（TaskInstance）
任务实例是任务的具体执行记录，每次执行生成一个新的实例，包含：
- **实例ID**：唯一执行标识
- **执行状态**：RUNNING、SUCCESS、FAILED、TIMEOUT等
- **开始时间**、**结束时间**
- **执行日志**和**执行结果**
- **重试次数**和**失败原因**

### 5.5 Worker节点
Worker是实际执行任务的计算节点，具有以下特性：
- **节点标识**：唯一ID和分组
- **资源能力**：CPU、内存、磁盘等
- **执行能力**：支持的任务类型
- **健康状态**：正常、离线、高负载等

## 6. 使用指南

### 6.1 通过Web界面管理任务

#### 6.1.1 创建简单任务
1. 登录Web管理界面（默认地址：http://localhost:8080）
2. 进入"任务管理" → "创建任务"
3. 填写任务信息：
   ```yaml
   任务名称: 每日数据备份
   任务类型: SHELL
   任务内容: |
     #!/bin/bash
     DATE=$(date +%Y%m%d)
     mysqldump -u root -p${DB_PASSWORD} task_scheduler > backup_${DATE}.sql
     gzip backup_${DATE}.sql
     scp backup_${DATE}.sql.gz backup-server:/backups/
   调度配置:
     类型: CRON
     表达式: 0 2 * * *  # 每天凌晨2点
     时区: Asia/Shanghai
   执行参数:
     DB_PASSWORD: yourpassword
   资源需求:
     CPU: 1核
     内存: 512MB
     磁盘: 1GB
   超时设置: 3600秒
   ```

#### 6.1.2 创建DAG工作流
1. 进入"工作流管理" → "创建工作流"
2. 可视化编辑DAG：
   - 添加任务节点
   - 设置节点间依赖关系
   - 配置分支条件（可选）
3. 配置工作流触发条件
4. 设置工作流参数和变量

### 6.2 使用API管理任务

#### 6.2.1 创建任务
```bash
curl -X POST http://localhost:8080/api/v1/tasks \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "name": "数据清洗任务",
    "type": "PYTHON",
    "content": "import pandas as pd\n\ndef clean_data():\n    # 数据清洗逻辑\n    pass",
    "trigger": {
      "type": "CRON",
      "expression": "0 3 * * *"
    },
    "parameters": {
      "input_file": "/data/raw/input.csv",
      "output_file": "/data/processed/output.csv"
    },
    "resources": {
      "cpu": 2,
      "memory": 1024,
      "disk": 5120
    }
  }'
```

#### 6.2.2 查询任务状态
```bash
# 查询特定任务状态
curl -X GET http://localhost:8080/api/v1/tasks/{taskId}/status \
  -H "Authorization: Bearer <token>"

# 查询任务执行历史
curl -X GET http://localhost:8080/api/v1/tasks/{taskId}/instances \
  -H "Authorization: Bearer <token>" \
  -G -d "page=0" -d "size=10"
```

#### 6.2.3 手动触发任务

#### 6.3.2 Python SDK
```python
from task_scheduler import TaskSchedulerClient
from task_scheduler.models import TaskType, CronTrigger

# 初始化客户端
client = TaskSchedulerClient(
    server_url="http://localhost:8080",
    api_key="your-api-key"
)

# 创建Python任务
task = client.create_task(
    name="Python数据分析任务",
    task_type=TaskType.PYTHON,
    content="""
import pandas as pd
import numpy as np

def process_data():
    df = pd.read_csv('/data/input.csv')
    # 数据处理逻辑
    result = df.groupby('category').sum()
    result.to_csv('/data/output.csv')
    return {'records_processed': len(df)}
""",
    trigger=CronTrigger(expression="0 4 * * *"),
    parameters={
        "input_path": "/data/raw/",
        "output_path": "/data/processed/"
    }
)

print(f"任务已创建: {task.id}")

# 手动执行任务
execution = client.execute_task(task.id, params={"batch_size": 1000})
print(f"执行已启动: {execution.id}")

# 监控执行状态
status = client.wait_for_completion(execution.id, timeout=3600)
print(f"执行状态: {status}")
```

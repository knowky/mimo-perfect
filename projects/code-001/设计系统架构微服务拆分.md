# **分布式电商系统架构设计：微服务拆分方案**

## **1. 设计理念与目标**
本设计遵循 **领域驱动设计 (DDD)** 、**高内聚低耦合**、**数据库自治**、**独立部署与扩展** 的核心原则。目标是构建一个具备**高可用性、高可扩展性、高容错性和可维护性**的分布式电商系统。

**核心设计目标：**
- **业务隔离：** 各服务边界清晰，独立演进。
- **技术异构：** 各服务可根据特点选择最适合的技术栈。
- **弹性伸缩：** 针对流量不均的模块（如商品浏览、秒杀）进行独立扩缩容。
- **故障隔离：** 单一服务故障不影响系统整体可用性。
- **数据自治：** 每个微服务拥有自己的数据库，避免紧耦合的数据访问。

## **2. 核心业务能力分析与领域划分**
基于电商业务流程，我们将系统划分为以下核心领域：

| 领域类型 | 业务领域 | 核心能力描述 |
| :--- | :--- | :--- |
| **核心域** | **商品域** | SKU、SPU管理、类目、属性、价格、商品详情 |
| **核心域** | **交易域** | 购物车、订单创建/履约/查询、售后服务 |
| **核心域** | **用户域** | 用户注册/登录、信息管理、地址管理 |
| **核心域** | **库存域** | 库存扣减/增加、库存查询、库存预占 |
| **支撑域** | **营销域** | 优惠券、满减、秒杀、积分、促销活动 |
| **支撑域** | **支付域** | 支付路由、支付单生成、对接第三方支付、对账 |
| **支撑域** | **物流域** | 运单管理、物流跟踪、发货/签收 |
| **通用域** | **认证授权域** | JWT/OAuth2生成与校验、权限管理 |
| **通用域** | **搜索推荐域** | 商品搜索、个性化推荐、热词分析 |
| **通用域** | **消息通知域** | 短信、邮件、站内信、APP Push |

### **3.1 核心业务服务**
| 服务名称 | 主要职责 | 关键技术点 | 数据库设计 |
| :--- | :--- | :--- | :--- |
| **用户服务 (UserService)** | 用户注册、登录、信息CRUD、地址管理。 | - JWT令牌生成与校验<br>- 密码加盐加密 | 独立库，分表（用户主表、地址表） |
| **商品服务 (ProductService)** | 商品信息管理（SPU/SKU）、类目属性管理、品牌管理。 | - ES构建商品搜索索引<br>- 使用缓存热点商品数据 | 独立库，主从读写分离 |
| **购物车服务 (CartService)** | 购物车的增删改查，合并。 | - **未登录：** Cookie/LocalStorage<br>- **已登录：** Redis Hash 存储 | 无持久化数据库，核心数据在Redis |
| **订单服务 (OrderService)** | 订单创建、查询、状态流转（待支付/已支付/已发货/完成/取消）。 | - **创建订单：** 分布式事务（Saga模式）<br>- 使用状态机管理订单状态 | 独立库，订单表、订单商品表、状态日志表 |
| **库存服务 (InventoryService)** | 库存预占、确认扣减、库存回补、库存查询。 | - **乐观锁**（`update set stock = stock - 1 where sku_id=? and stock >= 1`）<br>- Redis预扣库存 | 独立库，库存主表 |

### **3.2 支撑服务**
| 服务名称 | 主要职责 | 关键技术点 | 数据库设计 |
| :--- | :--- | :--- | :--- |
| **支付服务 (PayService)** | 创建支付单，调用微信/支付宝等支付渠道，处理支付回调，发起退款。 | - 对接多支付渠道的**适配器模式**<br>- 支付流水幂等性处理 | 独立库，支付流水表、对账表 |
| **营销服务 (PromotionService)** | 优惠券管理、满减规则计算、秒杀活动管理。 | - 规则引擎计算优惠<br>- 秒杀：Redis+Lua原子操作，流量削峰 | 独立库，活动表、优惠券模板表、用户优惠券表 |
| **物流服务 (LogisticsService)** | 对接第三方物流接口，管理运单，跟踪物流状态。 | - 定时任务轮询物流状态<br>- 物流状态推送 | 独立库，运单表、物流轨迹表 |
| **通知服务 (NotificationService)** | 统一发送短信、邮件、站内信、Push。 | - 消息队列消费，保证最终一致性<br>- 短信/邮件服务降级 | 独立库，消息模板表、发送记录表 |

### **3.3 平台与基础服务**
| 服务名称 | 主要职责 | 关键技术点 |
| :--- | :--- | :--- |
| **认证授权服务 (AuthService)** | 统一的用户认证（登录）、JWT令牌颁发与刷新、API权限校验。 | - OAuth2.0 / JWT<br>- RBAC权限模型 |
| **搜索推荐服务 (SearchService)** | 提供商品搜索（全文、筛选）、个性化推荐列表。 | - Elasticsearch 作为搜索引擎<br>- 协同过滤等推荐算法 |
| **API网关 (Gateway)** | 统一入口，路由转发，限流熔断，身份校验。 | - Spring Cloud Gateway / Kong<br>- Sentinel 熔断降级 |
| **BFF层 (Backend For Frontend)** | 为不同端（Web, App, 小程序）提供个性化的API聚合与裁剪。 | - GraphQL 或 RESTful 聚合API<br>- 可与网关合并或独立部署 |

## **4. 通信机制设计**
- **同步通信：** 服务间基于 **RESTful API (OpenFeign)** 或 **gRPC** 进行实时调用。适用于查询和需要立即响应的操作。
- **异步通信：** 通过 **消息队列 (RabbitMQ / RocketMQ / Kafka)** 实现事件驱动。适用于：
  - **订单服务** 发布“订单创建”事件 -> **库存服务**消费进行预扣，**营销服务**消费锁定优惠券。
  - **支付服务** 发布“支付成功”事件 -> **订单服务**消费更新状态，**物流服务**消费生成运单。
  - **通知服务** 消费各类业务事件发送通知。

## **5. 数据管理策略**
1.  **数据库 per 服务：** 每个微服务拥有独立的数据库实例，**严禁跨服务直接访问数据库**。
2.  **分布式事务：**
    - **强一致性场景 (如库存)：** 采用 **TCC (Try-Confirm-Cancel)** 模式。
    - **最终一致性场景 (如订单-支付-物流)：** 采用 **基于消息队列的 Saga 模式** 或 **本地消息表**。
3.  **数据查询：** 跨服务数据查询通过 **API组合** 或构建 **读模型 (CQRS)** 解决。例如，订单详情页需要用户地址、商品信息，由BFF层分别调用用户服务、商品服务进行组装。

## **6. 部署与运维架构**
- **容器化：** 所有服务使用 **Docker** 容器化。
- **编排与调度：** 使用 **Kubernetes (K8s)** 进行集群管理、服务部署、滚动更新、自动伸缩和健康检查。
- **配置管理：** 使用 **Nacos** 或 **Apollo** 作为统一配置中心。
- **服务注册与发现：** 使用 **Nacos** 或 **Consul**。
- **监控与告警：** **Prometheus** 采集指标 + **Grafana** 可视化 + **Alertmanager** 告警。
- **链路追踪：** **SkyWalking** 或 **Jaeger**，用于分布式调用链分析。
- **日志管理：** **ELK (Elasticsearch, Logstash, Kibana)** 或 **Loki** + **Grafana** 进行集中日志收集与分析。
- **持续集成/持续部署 (CI/CD)：** 使用 **Jenkins** 或 **GitLab CI** 流水线，实现代码提交到自动测试、构建、部署至K8s集群的全流程自动化。

## **7. 关键设计挑战与应对策略**
1.  **微服务边界的“度”：** 避免过度拆分导致“分布式单体”。遵循**一个服务由一个小团队维护**、**服务变更通常不需要修改其他服务**的原则。
2.  **服务间数据依赖：** 优先通过API同步查询。对于复杂查询，可考虑**事件驱动 + ES构建宽表**的读模型。
3.  **分布式系统复杂性：** 通过**统一的技术栈（Spring Cloud Alibaba）**、**完善的DevOps工具链**和**可观测性体系（监控、链路、日志）** 来管理复杂性。
4.  **安全：** API网关统一进行认证和限流。服务间通过内网通信，并可使用 **mTLS** 加强安全。

此架构设计为大型分布式电商系统提供了一个坚实、灵活且可扩展的骨架。在具体实现时，可根据业务规模和团队情况，选择从核心域（商品、用户、订单、库存）开始逐步构建和迭代。

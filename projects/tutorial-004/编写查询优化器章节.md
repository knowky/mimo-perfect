# 数据库内核实现教程 - 查询优化器章节

## 1. 查询优化器概述

### 1.1 查询优化器的核心作用
查询优化器是数据库管理系统的大脑，负责将SQL查询转换为高效的执行计划。一个优秀的优化器能够：
- 自动选择最优的执行路径
- 显著提升查询性能（通常可达数量级差异）
- 简化用户的工作，无需手动优化查询
- 适应数据分布和系统状态的变化

### 1.2 优化器在数据库架构中的位置
```
SQL语句 → 解析器 → 预处理器 → 优化器 → 执行引擎 → 结果集
                      ↑
                  元数据存储
                  统计信息
                  代价模型
```

### 1.3 查询优化面临的挑战
1. **搜索空间巨大**：n个表的连接有n!种顺序
2. **成本估计不准确**：统计信息可能存在偏差
3. **优化开销与执行性能的权衡**：不能花费过多时间优化
4. **复杂查询的处理**：子查询、窗口函数、递归查询等

## 2. 查询优化器架构

### 2.1 基于规则的优化（Rule-Based Optimization, RBO）
```
优点：
- 实现简单，易于理解
- 执行速度快（不需要统计数据）
- 可预测性强

缺点：
- 无法适应数据分布变化
- 难以处理复杂场景
- 性能提升有限

典型规则：
1. 选择谓词下推（Predicate Pushdown）
2. 投影下推（Projection Pushdown）
3. 常量折叠（Constant Folding）
4. 等值传播（Equality Propagation）
5. 子查询展开（Subquery Unnesting）
```

### 2.2 基于成本的优化（Cost-Based Optimization, CBO）
现代数据库系统广泛采用CBO，其核心组件：

```cpp

    }
```

### 3.2 逻辑计划生成

#### 3.2.1 从SQL到查询图
```cpp
LogicalPlan generate_logical_plan(const ParsedQuery& query) {
    LogicalPlan plan;
    
    // 1. 处理FROM子句，构建基本关系
    for (const auto& table : query.from_clause) {
        plan.add_node(ScanNode(table));
    }
    
    // 2. 处理WHERE子句，添加选择谓词
    for (const auto& pred : query.where_clause) {
        plan.add_predicate(pred);
    }
    
    // 3. 处理JOIN条件
    for (const auto& join : query.join_conditions) {
        plan.add_join_edge(join);
    }
    
    // 4. 处理GROUP BY和聚合
    if (query.has_aggregation) {
        plan = apply_aggregation(plan, query);
    }
    
    // 5. 处理ORDER BY和LIMIT
    plan = apply_order_and_limit(plan, query);
    
    return plan;
}
```

#### 3.2.2 子查询处理策略
```
策略1：子查询展开（Unnesting）
    将相关子查询转换为连接
    
策略2：物化（Materialization）
    将子查询结果物化为临时表
    
策略3：临时表（Temporary Table）
    将子查询结果存储在临时表中

示例：
-- 原始查询
SELECT * FROM employees 
WHERE salary > (SELECT AVG(salary) FROM employees);

-- 优化后（子查询物化）
temp = SELECT AVG(salary) FROM employees;
SELECT * FROM employees WHERE salary > temp;
```

#### 4.1.2 直方图类型
```
1. 等宽直方图（Equi-width Histogram）
   - 划分等宽的桶
   - 实现简单，但可能分布不均匀

2. 等高直方图（Equi-depth Histogram）
   - 每个桶包含大致相同数量的行
   - 更准确地表示数据分布

3. 最频值直方图（Most Common Values）
   - 记录最常见的值及其频率
   - 对高度偏斜的数据分布有效

4. Top-N直方图
   - 记录前N个最频繁的值
```

#### 4.2.2 选择率估计
```cpp
double estimate_selectivity(const ColumnStatistics& stats, 
                          const Predicate& pred) {
    if (pred.type == Predicate::EQUAL) {
        // 等值谓词选择率
        if (pred.value == NULL_VALUE) {
            return stats.null_count / (double)stats.num_rows;
        }
        
        // 检查是否是最频值
        if (stats.most_common_values.find(pred.value) != 
            stats.most_common_values.end()) {
            return stats.most_common_values[pred.value];
        }
        
        // 使用不同值数量估计
        return 1.0 / stats.num_distinct;
    }
    
    if (pred.type == Predicate::RANGE) {
        // 范围谓词选择率
        return estimate_range_selectivity(stats, pred.lower, pred.upper);
    }
    
    if (pred.type == Predicate::LIKE) {
        // LIKE谓词选择率
        return estimate_like_selectivity(pred.pattern);
    }
    
    // 复合谓词（AND, OR）
    return estimate_conjunctive_selectivity(stats, pred);
}

double estimate_join_selectivity(const ColumnStatistics& left_stats,
                               const ColumnStatistics& right_stats) {
    // 连接选择率估算
    double left_ndv = left_stats.num_distinct;
    double right_ndv = right_stats.num_distinct;
    
    // 简单的连接选择率估算公式
    return 1.0 / max(left_ndv, right_ndv);
}
```

#### 4.2.3 基数估算算法
```
算法1：独立性假设
    P(A AND B) = P(A) * P(B)
    简单但可能不准确

算法2：包含-排除原理
    P(A OR B) = P(A) + P(B) - P(A AND B)

算法3：基于直方图的估算
    使用直方图桶的边界和频率进行更精确的估算

算法4：抽样统计
    对大数据集进行抽样来估算选择率
```

### 4.3 连接顺序优化

#### 4.3.1 动态规划算法
```cpp
// 经典的System R动态规划算法
PhysicalPlan optimize_join_order(vector<TableId> tables,
                                JoinGraph join_graph,
                                vector<Predicate> predicates) {
    int n = tables.size();
    
    // dp[S]表示连接表集S的最优计划和成本
    unordered_map<BitSet, PlanCost> dp;
    
    // 初始化：单个表的计划
    for (int i = 0; i < n; i++) {
        BitSet s(1 << i);
        PlanCost plan = generate_scan_plan(tables[i]);
        dp[s] = plan;
    }
    
    // 动态规划：枚举所有可能的子集
    for (int size = 2; size <= n; size++) {
        for (BitSet s : subsets_of_size(tables, size)) {
            PlanCost best_plan = {NULL, INFINITE_COST};
            
            // 枚举所有可能的划分
            for (BitSet s1 : proper_subsets(s)) {
                BitSet s2 = s ^ s1;
                
                // 检查s1和s2之间的连接条件
                if (can_join(s1, s2, join_graph)) {
                    PlanCost plan1 = dp[s1];
                    PlanCost plan2 = dp[s2];
                    
                    // 生成连接计划
                    for (JoinMethod method : join_methods) {
                        PlanCost join_plan = generate_join_plan(
                            plan1, plan2, method);
                        
                        if (join_plan.cost < best_plan.cost) {
                            best_plan = join_plan;
                        }
                    }
                }
            }
            
            dp[s] = best_plan;
        }
    }
    
    // 返回连接所有表的最优计划
    BitSet all_tables((1 << n) - 1);
    return dp[all_tables].plan;
}
```

#### 4.3.2 启发式优化
```
启发式规则：
1. 选择性高的连接先执行（尽早减少数据量）
2. 小表先连接（嵌套循环连接时）
3. 利用索引（有索引的连接条件优先）
4. 避免笛卡尔积（确保连接图连通）

示例启发式：
void apply_heuristic_rules(LogicalPlan& plan) {
    // 规则1：将选择操作下推
    push_down_selections(plan);
    
    // 规则2：将投影操作下推
    push_down_projections(plan);
    
    // 规则3：重新排序连接以减少中间结果
    reorder_joins_by_selectivity(plan);
    
    // 规则4：将小表放在内循环
    optimize_join_order_for_nlj(plan);
}
```

### 4.4 访问路径选择

#### 4.4.1 扫描方式选择
```cpp
AccessPath choose_scan_method(TableId table,
                            vector<RangePredicate> predicates,
                            CostModel& cost_model) {
    vector<AccessPath> candidates;
    
    // 候选1：全表扫描
    candidates.push_back({
        .type = SCAN_SEQUENTIAL,
        .cost = cost_model.cost_seq_scan(table, predicates)
    });
    
    // 候选2：索引扫描
    for (IndexId index : get_table_indexes(table)) {
        if (can_use_index(index, predicates)) {
            candidates.push_back({
                .type = SCAN_INDEX,
                .index = index,
                .cost = cost_model.cost_index_scan(index, predicates)
            });
        }
    }
    
    // 候选3：聚簇索引扫描
    if (has_clustered_index(table)) {
        candidates.push_back({
            .type = SCAN_CLUSTERED_INDEX,
            .cost = cost_model.cost_clustered_scan(table, predicates)
        });
    }
    
    // 选择成本最低的访问路径
    return choose_minimum_cost(candidates);
}
```

#### 4.4.2 连接算法选择
```cpp
JoinAlgorithm choose_join_algorithm(PlanNode left,
                                  PlanNode right,
                                  JoinCondition condition,
                                  JoinStats stats,
                                  CostModel& cost_model) {
    vector<JoinAlgorithm> candidates;
    
    // 候选1：嵌套循环连接
    if (left.is_small() || has_index(right, condition)) {
        candidates.push_back({
            .type = JOIN_NESTED_LOOP,
            .cost = cost_model.cost_nested_loop_join(left, right, condition)
        });
    }
    
    // 候选2：哈希连接
    if (condition.is_equi_join() && 
        (left.is_small() || can_build_hash_table(left))) {
        candidates.push_back({
            .type = JOIN_HASH,
            .cost = cost_model.cost_hash_join(left, right, condition)
        });
    }
    
    // 候选3：归并连接
    if (condition.is_equi_join() && 
        (is_sorted(left, condition.left_keys) || 
         is_sorted(right, condition.right_keys))) {
        candidates.push_back({
            .type = JOIN_MERGE,
            .cost = cost_model.cost_merge_join(left, right, condition)
        });
    }
    
    // 候选4：索引嵌套循环连接
    if (has_index(right, condition.right_keys)) {
        candidates.push_back({
            .type = JOIN_INDEX_NESTED_LOOP,
            .cost = cost_model.cost_index_nl_join(left, right, condition)
        });
    }
    
    return choose_minimum_cost(candidates);
}
```

#### 5.1.1 谓词下推

#### 5.1.2 谓词简化
```cpp
void simplify_predicates(Predicate& pred) {
    // 常量折叠
    if (pred.is_constant_expression()) {
        pred = evaluate_constant(pred);
        return;
    }
    
    // 消除永真式和永假式
    if (pred.is_always_true()) {
        pred = TRUE_PREDICATE;
    } else if (pred.is_always_false()) {
        pred = FALSE_PREDICATE;
    }
    
    // 等值传播
    propagate_equalities(pred);
    
    // 冗余消除
    remove_redundant_predicates(pred);
}
```

### 5.2 连接优化

#### 5.2.1 外连接优化
```
优化技术：
1. 外连接重排序（在保证正确性的前提下）
2. 外连接转内连接（当存在非空约束时）
3. 消除不必要的外连接

示例：
-- 优化前
SELECT * FROM t1 LEFT JOIN t2 ON t1.id = t2.id
WHERE t2.value IS NOT NULL;

-- 优化后（外连接转内连接）
SELECT * FROM t1 INNER JOIN t2 ON t1.id = t2.id;
```

#### 5.2.2 连接消除
```cpp
bool can_eliminate_join(const JoinNode& join) {
    // 情况1：连接条件总是为真
    if (join.condition.is_always_true()) {
        // 检查是否为笛卡尔积（通常需要消除）
        return is_cartesian_product(join);
    }
    
    // 情况2：外连接且右表总是为空
    if (join.type == LEFT_JOIN && is_always_empty(join.right)) {
        return true;
    }
    
    // 情况3：内连接且右表的行不增加（功能依赖）
    if (join.type == INNER_JOIN && has_functional_dependency(join)) {
        return true;
    }
    
    return false;
}
```

### 5.3 子查询优化

#### 5.3.1 子查询展开
```cpp
LogicalPlan unnest_subquery(LogicalPlan plan,
                          SubqueryExpr subquery) {
    // 策略1：相关子查询转换为半连接
    if (subquery.is_correlated() && subquery.is_exists()) {
        return convert_to_semi_join(plan, subquery);
    }
    
    // 策略2：标量子查询转换为左连接
    if (subquery.is_scalar()) {
        return convert_to_left_join(plan, subquery);
    }
    
    // 策略3：IN子查询转换为内连接
    if (subquery.is_in_predicate()) {
        return convert_to_inner_join(plan, subquery);
    }
    
    // 策略4：物化子查询
    return materialize_subquery(plan, subquery);
}
```

#### 5.3.2 通用表表达式（CTE）优化
```
优化策略：
1. CTE内联（Inline）：当CTE只被引用一次时
2. CTE物化（Materialize）：当CTE被多次引用时
3. CTE下推：将谓词推入CTE定义

示例：
WITH dept_stats AS (
    SELECT dept_id, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY dept_id
)
SELECT e.name, e.salary, d.avg_salary
FROM employees e
JOIN dept_stats d ON e.dept_id = d.dept_id
WHERE e.salary > d.avg_salary;

优化可能：
- 物化CTE（如果被多次引用）
- 将WHERE条件推入CTE
- 使用窗口函数替代CTE
```

#### 5.4.2 聚合消除
```cpp
bool can_eliminate_aggregation(const AggregateNode& agg) {
    // 情况1：聚合键是唯一键（COUNT(*) = 1）
    if (agg.is_unique_group_by()) {
        return true;
    }
    
    // 情况2：聚合函数是MIN/MAX且存在索引
    if ((agg.function == MIN || agg.function == MAX) && 
        has_index_on_column(agg.column)) {
        return true;
    }
    
    // 情况3：聚合表达式是常量
    if (agg.is_constant_expression()) {
        return true;
    }
    
    return false;
}
```

```cpp
vector<PhysicalPlan> enumerate_bottom_up(LogicalPlan logical_plan) {
    vector<PhysicalPlan> plans;
    
    // 1. 为每个叶子节点生成扫描计划
    for (auto& leaf : logical_plan.get_leaves()) {
        auto scan_plans = generate_scan_plans(leaf);
        plans.insert(plans.end(), scan_plans.begin(), scan_plans.end());
    }
    
    // 2. 自底向上构建更大的计划
    for (int level = 1; level <= logical_plan.get_height(); level++) {
        vector<PhysicalPlan> next_level;
        
        for (auto& plan : plans) {
            // 尝试所有可能的操作
            auto transformed = apply_transformations(plan);
            next_level.insert(next_level.end(), 
                            transformed.begin(), transformed.end());
        }
        
        plans = next_level;
    }
    
    return plans;
}
```

```cpp
                GroupExpression new_expr = rule.apply(group);
                add_to_group(new_expr);
            }

        for (Implementation impl : implementations) {

                cost_and_memoize(phys_plan);
            }
        }
    }

            optimize_group(child);
        }
        
        // 计算当前表达式的最优成本

    }
};
```

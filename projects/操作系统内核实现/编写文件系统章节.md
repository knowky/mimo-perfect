# 第 8 章 文件系统

## 8.1 引言：文件系统的角色与抽象

文件系统是操作系统内核中最核心、最复杂的子系统之一。其首要职责是**为用户和应用程序提供一个持久、有序、层次分明的数据存储抽象**。通过将物理存储设备（如硬盘、固态硬盘）上无结构的线性块序列，组织成文件（命名的数据集合）和目录（文件的容器，可嵌套），文件系统极大地简化了数据管理。

在操作系统中，文件系统通常由三个主要层次构成：

1.  **逻辑文件系统 (Logical File System)**：处理所有与文件相关的元数据操作，如目录遍历、文件权限检查、文件创建与删除等。它定义了文件系统的逻辑结构。
2.  **文件组织模块 (File Organization Module)**：负责将逻辑文件块号映射到物理磁盘块号。它理解文件的物理存储布局。
3.  **基本文件系统 (Basic File System)**：负责向设备驱动程序发送通用的读写命令，处理磁盘块的物理I/O。

我们的实现将基于一个**简化的类ext2文件系统**，并着重于前两个层次。我们将设计并实现一个功能完整但规模可控的教学文件系统，以阐明核心概念。

## 8.2 文件系统架构与VFS

在类Unix系统中，**虚拟文件系统 (Virtual File System, VFS)** 是一个关键的抽象层。它定义了一个通用的文件系统接口，使得具体的文件系统（如ext4、XFS、Btrfs）可以以统一的方式被内核和用户访问。

**VFS的核心对象模型包括：**

-   **`struct superblock`**: 代表一个具体的已挂载文件系统实例，包含文件系统的元数据（如块大小、inode总数）。
-   **`struct inode`**: 代表文件系统中的一个文件或目录。它包含文件的元数据（大小、权限、时间戳、数据块指针），但不包含文件名。
-   **`struct dentry` (目录项)**: 代表一个目录条目，它将一个文件名（字符串）与其对应的`inode`关联起来，并维护目录树的缓存。
-   **`struct file`**: 代表一个被进程打开的文件。它包含文件的当前读写位置（偏移量）以及对底层`inode`和操作的引用。

我们的实现将遵循这一模型，定义自己的`superblock`、`inode`、`dentry`和`file`结构体。

## 8.3 磁盘布局设计

我们的教学文件系统将在一个虚拟的磁盘镜像上工作。设计一个清晰、稳定的磁盘布局是至关重要的。

**设计目标**：
-   简单明了，易于理解。
-   支持基本的文件和目录操作。
-   考虑一定的扩展性。

我们将采用类似ext2的**块组 (Block Group)** 布局，但简化到单个块组。

**磁盘总体布局如下图所示：**

```
┌──────────────────────────────────────────────────────┐
│ 超级块 (Superblock)                                  │ 块0
├──────────────────────────────────────────────────────┤
│ 块组描述符表 (Block Group Descriptor Table)          │ 块1
├──────────────────────────────────────────────────────┤
│ 数据块位图 (Block Bitmap)                            │ 块2
├──────────────────────────────────────────────────────┤
│ Inode位图 (Inode Bitmap)                             │ 块3
├──────────────────────────────────────────────────────┤
│ Inode表 (Inode Table)                                │ 块4 .. (4+INODE_TABLE_BLOCKS-1)
├──────────────────────────────────────────────────────┤
│ 数据块 (Data Blocks)                                 │ 其余所有块
└──────────────────────────────────────────────────────┘
```

**关键设计参数**：
-   块大小 (`BLOCK_SIZE`): 通常为 1024, 2048, 4096 字节。为简化，我们使用 **1024字节**。
-   Inode大小 (`INODE_SIZE`): 我们定义为 **128字节**（一个常见值）。
-   每块的Inode数 (`INODES_PER_BLOCK`): `BLOCK_SIZE / INODE_SIZE` = 8。
-   总Inode数 (`TOTAL_INODES`): 由格式化工具决定，假设为128。
-   Inode表占用块数 (`INODE_TABLE_BLOCKS`): `ceil(TOTAL_INODES / INODES_PER_BLOCK)` = 16。
-   总磁盘块数 (`TOTAL_BLOCKS`): 由磁盘镜像大小决定，例如1MB镜像有1024块。

### 8.3.1 超级块 (Superblock)

超级块位于磁盘的固定位置（块0），是文件系统的“心脏”，包含全局元数据。

```c
// fs/include/super.h
#define FS_MAGIC 0x4D594653 // “MYFS” 的ASCII码
#define BLOCK_SIZE 1024
#define INODE_SIZE 128

struct myfs_superblock {
    uint32_t s_magic;          // 文件系统魔数，用于校验
    uint32_t s_inodes_count;   // 总Inode数量
    uint32_t s_blocks_count;   // 总数据块数量
    uint32_t s_free_inodes_count;
    uint32_t s_free_blocks_count;
    uint32_t s_first_data_block; // 第一个数据块的块号（通常为0或1）
    uint32_t s_log_block_size;   // 块大小 = 1024 << s_log_block_size (我们这里为0)
    uint32_t s_inodes_per_group; // 本块组的Inode数（简化版等于s_inodes_count）
    uint32_t s_blocks_per_group; // 本块组的块数
    uint32_t s_inodes_table_block; // Inode表起始块号
    uint32_t s_block_bitmap_block; // 数据块位图起始块号
    uint32_t s_inode_bitmap_block; // Inode位图起始块号
    uint8_t  s_uuid[16];       // 文件系统唯一标识符（简化版可忽略）
    char     s_volume_name[16]; // 卷标
    uint8_t  reserved[BLOCK_SIZE - 128]; // 填充至块大小
} __attribute__((packed));
```

### 8.3.2 Inode结构

Inode是文件系统的核心数据结构，一个Inode代表一个文件或目录。

```c
// fs/include/inode.h
struct myfs_inode {
    uint16_t i_mode;           // 文件类型和权限 (rwx)
    uint16_t i_uid;            // 所有者用户ID
    uint32_t i_size;           // 文件大小（字节）
    uint32_t i_atime;          // 最后访问时间
    uint32_t i_ctime;          // 创建时间/Inode修改时间
    uint32_t i_mtime;          // 最后内容修改时间
    uint32_t i_dtime;          // 删除时间（若已删除）
    uint16_t i_gid;            // 所有者组ID
    uint16_t i_links_count;    // 硬链接计数
    uint32_t i_blocks;         // 文件占用的磁盘块数（512字节扇区为单位）
    uint32_t i_flags;          // 文件标志
    uint32_t i_block[15];      // 数据块指针数组
    // i_block[0..11]: 直接块指针 (12个)
    // i_block[12]: 一级间接块指针
    // i_block[13]: 二级间接块指针
    // i_block[14]: 三级间接块指针
    uint8_t  reserved[INODE_SIZE - 128]; // 填充至INODE_SIZE
} __attribute__((packed));
```

**数据块寻址方案**：
-   **直接指针** (`i_block[0-11]`): 直接指向数据块，适合小文件。
-   **间接指针** (`i_block[12]`): 指向一个“间接块”，该块中存储的是数据块地址列表。
-   **二级间接指针** (`i_block[13]`): 指向一个“间接块”，该块中存储的是“一级间接块”的地址。
-   **三级间接指针** (`i_block[14]`): 以此类推，支持超大文件。

我们的实现将首先支持直接块和一级间接块。

## 8.5 关键操作实现

我们将概述几个核心操作的数据流和伪代码实现。

### 8.5.1 文件系统挂载 (`mount`)

当执行`mount`命令时，内核会调用特定文件系统的`mount`方法。

```c
// 伪代码流程
int myfs_mount(struct block_device *bdev, ...) {
    // 1. 从磁盘读取块0（超级块）到内存
    struct myfs_superblock *sb_disk = read_block(bdev, 0);

    // 2. 校验魔数
    if (sb_disk->s_magic != FS_MAGIC) {
        return -EINVAL;
    }

    // 3. 创建VFS超级块，并关联myfs_sb_info
    struct super_block *sb = sget(...); // 获取或创建VFS superblock
    struct myfs_sb_info *sbi = kzalloc(sizeof(*sbi), GFP_KERNEL);
    sbi->s_es = sb_disk;
    sb->s_fs_info = sbi;
    sb->s_op = &myfs_super_ops; // 设置超级块操作函数表

    // 4. 读取并验证根目录Inode (通常Inode号为2)
    struct inode *root_inode = myfs_iget(sb, MYFS_ROOT_INO);
    // 5. 为根目录创建dentry，并作为挂载点的dentry
    sb->s_root = d_make_root(root_inode);

    return 0;
}
```

### 8.5.2 查找路径与Inode获取 (`iget`)

`myfs_iget`负责根据Inode号从磁盘读取或从缓存中获取内存Inode。

```c
struct inode *myfs_iget(struct super_block *sb, unsigned long ino) {
    // 1. 在VFS的Inode缓存中查找
    struct inode *inode = iget_locked(sb, ino);
    if (!inode)
        return ERR_PTR(-ENOMEM);

    // 2. 如果是新读取的（未初始化）
    if (inode->i_state & I_NEW) {
        struct myfs_inode_info *ei = MYFS_I(inode);
        // 3. 计算Inode所在的磁盘块和偏移量
        // ino 是从1开始的编号，磁盘Inode从0开始存储
        uint32_t inode_block = 4 + (ino - 1) / (BLOCK_SIZE / INODE_SIZE); // 4是Inode表起始块
        uint32_t inode_offset = ((ino - 1) % (BLOCK_SIZE / INODE_SIZE)) * INODE_SIZE;

        // 4. 读取该磁盘块
        struct buffer_head *bh = sb_bread(sb, inode_block);
        struct myfs_inode *raw_inode = (struct myfs_inode *)(bh->b_data + inode_offset);

        // 5. 将磁盘Inode字段复制到内存myfs_inode_info
        ei->i_block[0] = raw_inode->i_block[0];
        // ... 复制其他字段

        // 6. 初始化VFS inode通用字段
        inode->i_mode = raw_inode->i_mode;
        inode->i_size = raw_inode->i_size;
        inode->i_op = &myfs_inode_ops; // 设置Inode操作表
        inode->i_fop = &myfs_file_ops; // 对于普通文件，设置文件操作表
        if (S_ISDIR(inode->i_mode))
            inode->i_fop = &myfs_dir_ops; // 对于目录，设置目录操作表

        brelse(bh);
        unlock_new_inode(inode); // 唤醒等待该Inode的进程
    }
    return inode;
}
```

### 8.5.3 文件读取 (`read`)

文件读取需要将逻辑文件偏移量转换为物理磁盘块，然后读取数据。

```c
// 伪代码
ssize_t myfs_file_read(struct file *file, char __user *buf, size_t count, loff_t *ppos) {
    struct inode *inode = file_inode(file);
    struct myfs_inode_info *ei = MYFS_I(inode);
    loff_t pos = *ppos;
    size_t bytes_read = 0;

    while (count > 0 && pos < inode->i_size) {
        // 1. 计算当前偏移量所在的文件逻辑块号和块内偏移
        uint32_t logical_block = pos / BLOCK_SIZE;
        uint32_t block_offset = pos % BLOCK_SIZE;

        // 2. 将逻辑块号映射到物理磁盘块号 (myfs_bmap)
        uint32_t physical_block = myfs_bmap(inode, logical_block);
        if (physical_block == 0) { // 稀疏文件或错误
            // 处理空洞或返回错误
            break;
        }

        // 3. 从块缓存中读取该物理块
        struct buffer_head *bh = sb_bread(inode->i_sb, physical_block);
        if (!bh) {
            break; // I/O错误
        }

        // 4. 计算本次可拷贝到用户空间的字节数
        size_t to_copy = min(count, BLOCK_SIZE - block_offset);
        to_copy = min(to_copy, inode->i_size - pos);

        // 5. 从缓冲区拷贝数据到用户空间
        if (copy_to_user(buf, bh->b_data + block_offset, to_copy)) {
            brelse(bh);
            return -EFAULT;
        }

        brelse(bh);
        // 6. 更新计数器和指针
        buf += to_copy;
        pos += to_copy;
        count -= to_copy;
        bytes_read += to_copy;
    }

    *ppos = pos;
    return bytes_read;
}

// 辅助函数：逻辑块号 -> 物理块号
uint32_t myfs_bmap(struct inode *inode, uint32_t logical_block) {
    struct myfs_inode_info *ei = MYFS_I(inode);
    if (logical_block < 12) {
        // 直接块
        return ei->i_block[logical_block];
    } else if (logical_block < 12 + (BLOCK_SIZE / 4)) {
        // 一级间接块
        logical_block -= 12;
        if (ei->i_block[12] == 0) return 0; // 空洞
        // 读取间接块
        struct buffer_head *bh = sb_bread(inode->i_sb, ei->i_block[12]);
        uint32_t *indirect = (uint32_t *)bh->b_data;
        uint32_t block = indirect[logical_block];
        brelse(bh);
        return block;
    } else {
        // 暂不支持二级间接及以上
        return 0;
    }
}
```

### 8.5.4 创建文件 (`creat` / `open` with O_CREAT)

创建文件涉及分配Inode、分配数据块（可选）、在父目录中添加目录项等。

```c
// 伪代码
int myfs_create(struct inode *dir, struct dentry *dentry, umode_t mode, ...) {
    // 1. 在父目录的数据块中查找，确保要创建的文件名不存在
    if (myfs_lookup(dir, dentry)) {
        return -EEXIST;
    }

    // 2. 分配一个空闲Inode (myfs_alloc_inode)
    struct inode *inode = myfs_new_inode(dir, mode);
    if (IS_ERR(inode)) {
        return PTR_ERR(inode);
    }

    // 3. 初始化新Inode的字段
    inode->i_op = &myfs_inode_ops;
    inode->i_fop = &myfs_file_ops;
    inode->i_size = 0; // 新文件大小为0

    // 4. 在父目录的数据块中添加一个新的目录项（文件名，新Inode号）
    int err = myfs_add_link(dentry, inode);
    if (err) {
        // 清理已分配的Inode
        myfs_free_inode(inode);
        return err;
    }

    // 5. 将新Inode关联到VFS dentry
    d_instantiate(dentry, inode);
    return 0;
}
```

## 8.6 错误处理与一致性

文件系统操作的原子性和一致性至关重要。在我们的简化实现中，可能采用以下策略：

1.  **写时更新 (Copy-on-Write)**：修改数据块时，先写入新块，再更新指针。这能避免部分写入导致的不一致。
2.  **日志 (Journaling)**：记录下所有将要进行的修改（日志），然后执行修改，最后标记日志完成。崩溃后可通过重放日志来恢复一致性。ext3/ext4等现代文件系统都采用此技术。
3.  **fsck (文件系统检查)**：在系统启动时，运行`fsck`工具来扫描并修复不一致。它会检查超级块、Inode、目录项和块位图之间的逻辑关系。

**在我们的教学文件系统中**，我们将优先考虑正确性而非极致的性能。对于关键元数据修改（如分配/释放Inode或块），应按顺序更新**磁盘位图**、**Inode表**和**数据块**，并确保在标记某个资源“已使用”之前，该资源本身已被正确初始化。

## 8.7 测试与调试

一个有效的文件系统需要严格的测试。

1.  **用户空间测试**：在用户空间编写测试程序，通过系统调用（`open`, `read`, `write`, `stat`, `mkdir`等）与我们的文件系统交互。
2.  **文件系统镜像工具**：编写一个用户态的格式化工具（`mkfs.myfs`），用于在磁盘镜像文件上创建文件系统结构。
3.  **调试手段**：
    -   在内核中添加`printk`语句跟踪关键操作。
    -   使用`debugfs`或类似工具直接检查文件系统镜像。
    -   在VFS层面设置`tracepoint`，跟踪系统调用到文件系统操作的执行路径。

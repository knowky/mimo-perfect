## **1. 项目概述**

### **1.1 项目目标**
构建一个高可用、高性能、可水平扩展的分布式即时通讯系统，支持单聊、群聊、文件传输、消息推送及实时状态同步等功能。

### **1.2 核心功能**
- 用户注册/登录/个人资料管理
- 一对一单聊与多人群聊
- 文字、图片、文件、表情消息
- 消息已读回执与离线消息
- 在线状态、输入提示、消息漫游
- 会话管理与历史记录查询

## **2. 系统架构设计**

### **2.1 整体架构图**
```
[客户端层] 
  │
  ▼
[接入层] 
  ├─ WebSocket 长连接网关（主通道）
  ├─ HTTP API 网关（RESTful 接口）
  └─ MQTT 协议适配器（可选，用于物联网场景）
  │
  ▼
[业务服务层]（微服务集群）
  ├─ 用户服务（User Service）
  ├─ 关系服务（Relationship Service）
  ├─ 消息服务（Message Service）
  ├─ 群组服务（Group Service）
  ├─ 会话服务（Session Service）
  └─ 推送服务（Push Service）
  │
  ▼
[数据层]
  ├─ 关系型数据库（MySQL）：用户、群组基础信息
  ├─ NoSQL（MongoDB/Redis）：消息存储、会话列表、在线状态
  ├─ 消息队列（Kafka/RocketMQ）：消息异步分发
  └─ 分布式缓存（Redis Cluster）：热点数据、会话状态
  │
  ▼
[基础设施层]
  ├─ 服务发现与配置中心（Nacos）
  ├─ 链路追踪（SkyWalking）
  ├─ 日志系统（ELK）
  └─ 监控告警（Prometheus + Grafana）
```

### **2.2 通信协议选择**
| 协议       | 适用场景                     | 优点                           | 缺点                     |
|------------|------------------------------|--------------------------------|--------------------------|
| WebSocket  | 主推协议，全双工实时通信     | 低延迟、服务端可主动推送       | 需维护长连接，负载均衡复杂 |
| MQTT       | 移动端、弱网络环境           | 轻量、支持离线消息、QoS等级    | 协议解析复杂，需Broker   |
| HTTP Long Polling | 兼容老旧客户端          | 无需特殊协议支持               | 延迟高、服务端压力大     |

**推荐方案**：主流客户端优先使用 **WebSocket**，移动端备选 **MQTT**，Web端兼容 **SSE（Server-Sent Events）**。

### **3.2 消息模块**
#### **消息存储方案**
```
方案1（写扩散）：
  消息写入后，为每个接收者生成一条消息记录存入其收件箱。
  优点：查询快，支持已读标记
  缺点：存储成本高，群消息写放大严重

方案2（读扩散）：
  消息只存储一份，接收者通过时间线拉取。
  优点：写入简单，存储空间小
  缺点：查询复杂，需合并多时间线

推荐方案：单聊采用写扩散，群聊采用读扩散（结合推拉结合模式）。
```

#### **消息数据结构（MongoDB示例）**
```json
{
  "_id": "msg_20230801120000_abc123",
  "conversation_id": "conv_uid1_uid2",
  "sender_id": "uid_001",
  "type": "text|image|file|audio|video",
  "content": {
    "text": "Hello!",
    "image": { "url": "http://cdn/img.png", "width": 100, "height": 100 },
    "file": { "url": "http://cdn/file.pdf", "size": 1024, "name": "report.pdf" }
  },
  "status": "sent|delivered|read",
  "client_id": "client_abc",
  "server_id": "msg_20230801120000_abc123",
  "timestamp": 1690873200000,
  "mentioned_users": ["uid_002"]
}
```

#### **消息投递流程（单聊示例）**
```
1. 客户端A → 服务器：发送消息（携带client_msg_id）
2. 服务器生成server_msg_id，写入消息存储
3. 服务器查询接收方B的在线状态：
   - 在线：通过WebSocket直接下发消息
   - 离线：推送到离线消息队列，存储到离线箱
4. 服务器向客户端A返回ACK（携带server_msg_id）
5. 客户端A收到ACK后，更新本地消息状态
```

#### **群消息扩散策略**
```
1. 发送者 → 服务器：发送群消息
2. 服务器写入消息存储（读扩散）
3. 服务器查询群成员列表（分页拉取）
4. 在线成员：直接推送
5. 离线成员：写入每个成员的离线消息队列（或写扩散到个人收件箱）
6. 批量ACK：服务器合并多个成员的ACK响应给发送者
```

### **3.4 会话模块**
#### **会话列表（Redis Sorted Set）**
```
Key: user:{uid}:conversations
Score: 消息时间戳
Member: conversation_id

操作示例：
# 添加/更新会话
ZADD user:uid1:conversations 1690873200000 conv_uid1_uid2

# 获取最近会话列表
ZREVRANGE user:uid1:conversations 0 19 WITHSCORES
```

### **3.5 在线状态管理**
```
方案：Redis Bitmap + 心跳机制
Key: online:status:{date} (如 online:status:20230801)
BitOffset: 用户uid的hash值
Value: 1表示在线，0表示离线

心跳间隔：客户端每30秒发送一次心跳包
超时判断：服务端90秒未收到心跳，标记为离线
```

## **4. 关键技术实现细节**

### **4.1 WebSocket连接管理**
#### **连接握手与认证**
```javascript
// 客户端连接示例
const ws = new WebSocket('wss://im.example.com/ws?token=xxxxx');

// 服务端处理
wss.on('connection', (ws, req) => {
  const token = new URL(req.url, 'http://localhost').searchParams.get('token');
  const user = verifyToken(token); // 验证JWT
  
  if (!user) {
    ws.close(4001, 'Unauthorized');
    return;
  }
  
  // 保存连接映射：uid -> [connection1, connection2, ...]
  connectionManager.add(user.uid, ws);
  
  // 发送心跳请求
  startHeartbeat(ws);
});
```

#### **连接多设备同步**
```
同一用户多设备登录策略：
1. 允许同平台（如手机+手机）同时在线
2. 消息多端同步投递
3. 会话状态（已读）同步更新
4. 设备管理：可单独下线指定设备
```

### **4.2 消息可靠投递（QoS机制）**
```
客户端 → 服务器：发送消息（带client_msg_id）
服务器 → 客户端：返回ACK（带server_msg_id）

超时重传机制：
1. 客户端设置消息发送超时（如5秒）
2. 超时未收到ACK，客户端重传（相同client_msg_id）
3. 服务端根据client_msg_id去重，保证幂等性

消息顺序性保证：
1. 每个会话内使用单调递增的序列号（sequence）
2. 客户端检测序列号连续性，发现丢序时请求补推
```

### **4.3 离线消息处理**
```python
# 离线消息队列设计（Redis List）
Key: offline:{uid}
Value: 消息ID列表

# 拉取离线消息流程
def fetch_offline_messages(uid, last_msg_id=None):
    # 1. 从离线队列获取消息ID列表
    msg_ids = redis.lrange(f'offline:{uid}', 0, -1)
    
    # 2. 批量获取消息详情
    messages = mongo.message.find({'_id': {'$in': msg_ids}})
    
    # 3. 删除已拉取的离线消息
    redis.delete(f'offline:{uid}')
    
    # 4. 更新会话最后消息
    update_conversations(uid, messages)
    
    return messages
```

## **5. 数据库设计与优化**

### **5.1 分库分表策略**
```
用户表：按uid hash分16个库，每库16个表（共256个分表）
消息表：按conversation_id hash分库，按时间分表（月表）
群组表：按group_id hash分库

分片键选择：
- 用户相关查询：uid
- 会话相关查询：conversation_id
- 群组相关查询：group_id
```

### **5.2 缓存架构**
```
L1缓存（本地缓存）：Guava Cache，缓存用户基本信息、群组信息
L2缓存（分布式缓存）：Redis Cluster
  - 用户在线状态：Bitmap
  - 会话列表：Sorted Set
  - 未读消息数：String (INCR操作)
  - 热点会话：ZSet缓存最近100条消息
```

### **5.3 消息存储归档**
```
热数据：最近3个月消息，存储在SSD MongoDB
温数据：3-12个月消息，存储在HDD MongoDB
冷数据：1年以上消息，归档到对象存储（S3/HDFS）

归档流程：
1. 定时任务扫描过期消息
2. 压缩打包（按会话归档）
3. 上传至对象存储
4. 删除原数据，记录归档索引
```

## **7. 安全设计**

### **7.1 传输安全**
```
1. 全链路HTTPS/WSS加密
2. 敏感数据（密码、token）不在URL中传输
3. 消息内容端到端加密（可选，使用Signal协议）
4. 防重放攻击：消息携带时间戳+随机数，服务端校验时效性
```

### **7.2 访问控制**
```java
// 鉴权拦截器示例
public class AuthInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request, 
                           HttpServletResponse response, 
                           Object handler) {
        String token = request.getHeader("Authorization");
        if (token == null || !token.startsWith("Bearer ")) {
            response.setStatus(401);
            return false;
        }
        
        try {
            User user = JWTUtil.parse(token.substring(7));
            request.setAttribute("currentUser", user);
            return true;
        } catch (JWTException e) {
            response.setStatus(401);
            return false;
        }
    }
}
```

## **8. 性能优化策略**

### **8.1 消息批量处理**
```go
// 消息批量写入示例（Go语言）
type MessageBatch struct {
    buffer chan *Message
    ticker *time.Ticker
}

func (b *MessageBatch) Start() {
    b.ticker = time.NewTicker(100 * time.Millisecond)
    go func() {
        for {
            select {
            case <-b.ticker.C:
                b.flush()
            case msg := <-b.buffer:
                b.messages = append(b.messages, msg)
                if len(b.messages) >= 100 {
                    b.flush()
                }
            }
        }
    }()
}

func (b *MessageBatch) flush() {
    if len(b.messages) == 0 {
        return
    }
    
    // 批量写入MongoDB
    bulk := mongoDB.Collection("messages").Bulk()
    for _, msg := range b.messages {
        bulk.Insert(msg)
    }
    bulk.Run()
    
    // 批量推送到Kafka
    kafkaProducer.SendBatch(b.messages)
    
    b.messages = b.messages[:0]
}
```
